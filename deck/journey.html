Why this is not the old curriculum

AI changed what a junior is worth.

The same six months, redesigned around three things that are now true and were not true three years ago.

SHIFT 01

Writing got cheap. Verifying did not.

Producing a repository pattern from memory is no longer a scarce skill. Looking at 200 generated lines and knowing they are wrong is. Reading, debugging and review move to week two, not week twenty.

SHIFT 02

Fundamentals matter more, not less.

AI collapses the time to a working app. It does not collapse the time to a working mental model. The gap between someone who understands what their code does and someone who does not is now the whole difference in value.

SHIFT 03

The failure mode is new.

The old risk was quitting after three days stuck. The new risk is shipping six impressive projects, explaining none of them, and failing the first interview. Every assessment here is built to catch that.

The structure

Two tracks. One project. Every week.

The frontend never runs as a separate course. Each week the React side consumes exactly what the C# side produced, so the two halves teach each other.

Backend track

  • C# fundamentals, then the debugger before anything else
  • Collections, files, object orientation, generics, LINQ
  • Layered architecture, EF Core, SQL Server
  • ASP.NET Core Web APIs, clean architecture, testing
  • Auth, caching, queues, payments, real time
  • Performance, distributed systems, security, operations
same project

Frontend track

  • HTML, CSS and the DOM by hand, no framework
  • Modern JavaScript and the event loop, drawn on paper
  • React components, state, forms, then TypeScript
  • Next.js App Router, server components, TanStack Query
  • Design systems, streaming UI, upload and checkout flows
  • Core Web Vitals, accessibility, error tracking
The rule that governs everything

The AI licence.

How much a student may delegate changes as they grow. The tier is stated on every weekly brief and enforced in review.

Weeks 1 to 4
Red

AI is a tutor, never a typist. Explanations, quizzes, practice sets and review of code the student already wrote. Tab completion off.

Check: can you retype the file from an empty editor?

Weeks 5 to 12
Yellow

AI writes boilerplate. You write the thinking. Scaffolding, config, test skeletons, three-approaches-and-tradeoffs questions.

Check: a random line is picked in review. One "I don't know" returns the work.

Weeks 13 to 24
Green

AI implements. You review. Written spec before generation, line by line review after, full ownership of the result. This is the actual job.

Check: "the AI wrote it" is not an explanation, here or in a post-mortem.

Every student submits an ai-log.md each week: what was delegated, what came back, what they changed and why. It is assessed.

Phase one

Fundamentals

Weeks 1 to 4 / Red licence
WEEK 01Variables, logic and the debugger. Breakpoints in week one, before print statements become a habit. Console calculator, plus a hand-built HTML page.
WEEK 02Collections, files, modern JavaScript. The calculator remembers. The event loop gets drawn on paper.
WEEK 03Object orientation and first React. The school project begins, designed on paper before a class is typed.
WEEK 04Generics, LINQ and React state. One repository serving four types. Twenty LINQ queries written by hand, wrong, repeatedly.
By the end

A school modelled properly in C# with full CRUD, and a React directory with forms, validation and routing.

Persistence and APIs

Weeks 5 to 8 / Yellow opens
WEEK 05Architecture, TypeScript, saving to disk. Four projects, dependencies pointing inward, and the move to Next.js.
WEEK 06EF Core and SQL Server. Thirty SQL queries by hand before the ORM is allowed anywhere near them.
WEEK 07Real APIs. A Todo API written entirely by hand as the HTTP gym, then the school goes over the wire.

03
Phase three

Production concerns

Weeks 9 to 12 / Yellow
WEEK 09Integration and end to end testing. Real database in a container, real browser in Playwright.
WEEK 10Authentication and authorization. Day seven is spent attacking their own auth and writing down what worked.
WEEK 11What real APIs have. Logging, caching, rate limits, secrets, health checks, and 50,000 seeded students to break things.

The app leaves the laptop. Public URL, green pipeline, one-command local stack, and a runbook.

04
Phase four

Depth

Weeks 13 to 18 / Green licence
WEEK 13Frontend craft. Capstone starts. Design tokens, component library, profiling before optimising.
WEEK 14Real time, uploads, and a cold codebase. Two days inside a repository they have never seen, with a ticket.
WEEK 15Background jobs and payments. The duplicate webhook drill. Send it five times and see if the user is charged twice.

05
Phase five

AI engineering, and the sprint

Weeks 19 to 22 / Green
WEEK 19Building with LLMs. Streaming, structured output, tool use, cost caps, and building the non-AI version first to check the model is needed at all.
WEEK 20Retrieval and evaluation. Anyone can demo RAG. Putting a number on whether it works is the rare skill.

The final gate

Three assessments, all with AI switched off, because what remains when the tools are removed is the honest measure of six months.

Assessment

Five mechanisms generated code cannot pass.

01

The weekly build

Backend and frontend, against explicit acceptance criteria printed in that week's brief. Ticked honestly or not at all.

02

Explain it back

Live, out loud, editor closed. Nothing counts as done until it survives this. Code that works but cannot be explained scores zero.

03

The blank editor drill

Thirty minutes, no AI, no internet. Rebuild something small from that week from nothing.

04

Planted-defect review

Code that compiles, passes its tests and hides real bugs, including one that only appears under concurrency. Finding them is the job.

05

The cold codebase

Two days in a repository they have never seen, with a ticket. Reading unfamiliar code is what month one of a real job actually is.

Outcome

What they can do on the last day.

  • Design a system for ten million users and name where it breaks first
  • Build and ship a layered .NET API with a real database
  • Build a typed Next.js frontend that is fast and accessible
  • Write tests that fail when the feature is broken
  • Find an access control hole in code that looks fine
  • Take a service down and bring it back, with the runbook they wrote
  • Add an AI feature and prove with numbers that it works
  • Read a codebase they have never seen and ship a change in it
  • Review a pull request and find something real
  • Explain every decision in their own product, without help

The tools will keep getting better at writing code. They will not get better at deciding what should be built, judging whether the answer is right, or being accountable when it is wrong. That is the job this programme protects.
